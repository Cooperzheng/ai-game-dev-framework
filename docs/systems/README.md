# 模块设计与实现模板

本页是框架的模板说明，不是游戏模块目录。游戏中的一个模块放在 `docs/modules/模块名/`（或本地化的 `docs/模块/模块名/`），设计与实现同目录。完整职责见[文档组织](../standards/README.md#按模块组织项目文档)。已有项目沿用有效正文，不为凑齐文件创建空实现。

设计正文使用 `DESIGN.md`（或 `设计.md`），只写玩家能做什么、规则如何运作、预期感受及当前设计；不写代码路径、状态机、依赖、算法或实现步骤。不预建空模块。

```markdown
# 系统名称

## 已确认设计
用户明确的体验目标、规则与排除项，简要注明来源和认可范围。
已确认但尚未实现的要求保留，并注明差距；没有明确确认就写“暂无”，不补造。

## AI 当前方案
当前采用的功能、操作、反馈、数值和系统之间的玩法关系。
写清玩家体验差别，按需注明已实现、尚未实现或效果未达标。
这些方案在已确认边界与任务范围内可调整，不因实现就升级为用户确认。
```

例如：用户确认“主动躲避，不引入体力管理”。AI 当前方案可以写“已实现闪避和翻滚；闪避距离短、恢复快，翻滚距离长、恢复慢，两者共享冷却”。冷却值若未经明确确认，AI 可调校；不能自行加入体力消耗。

候选方案尚未采用时不写成当前规则。尝试过程按需要留在可选 Plan；必要技术知识放代码注释或已有工程说明，不强制另建文档。用户认可某项 AI 方案后只将认可的部分转入已确认设计，避免两处重复维护。

实现正文按需使用同目录的 `IMPLEMENTATION.md`（或 `实现.md`），维护实现入口、必要参数与接口、制作前提、专用检查和有效复验结论。复验注明日期、版本或草稿身份、检查范围、结果与未决问题；新结论替换失效状态，不逐轮追加报告。跨模块契约由工程总览维护后引用，图像来源和许可保留在资产目录。
