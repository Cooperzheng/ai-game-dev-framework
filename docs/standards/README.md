# 专项规范的组织与维护

一条规则只维护一份详细正文，其余入口引用。先合并已有等效内容，不预建空规范、Skill 或庞大目录体系；项目案例不自动变成所有项目的要求。

## 文档与 Skill 分工

AGENTS 保存权限边界、读取条件与核心底线；专项规范保存适用条件和可观察的质量标准；设计与技术事实归所属正文。Skill 按需保存可复用知识、流程、脚本与模板，引用同一规范，不形成第二套强制规则，也不替代必读路由。

## 阅读路由

路由写清触发条件、正文与底线。规范可以跨目录适用；使用局部规则前核实宿主支持，链接存在不代表已加载，不支持自动加载时显式读取。

## 按模块组织项目文档

从同一模块目录找到设计与实现。文件名可以本地化，已有等效结构沿用；每份正文只维护一个模块或一种公共职责，只建立有内容的文件。

| 位置 | 单一职责 |
| --- | --- |
| 根 README | 人和 AI 共用的完整导航，模块设计与实现成对列出 |
| docs/PROJECT.md | 项目方向、核心要求与确认范围 |
| docs/modules/模块名/DESIGN.md | 玩家体验、规则、操作、已确认设计与 AI 当前方案 |
| 同目录 IMPLEMENTATION.md | 实现、参数、制作、专用操作、有效复验与未决问题，按需建立 |
| docs/engineering/ | 跨模块架构、全仓运行维护与资产管线 |
| docs/standards/ | 质量标准与工作规范 |
| docs/references/ | 研究参考、来源与按项目政策保留的附件 |
| docs/release/ | 玩家说明、发行许可等交付输入 |
| docs/local/ | 本地验收、可选计划、历史展示与配图，默认不上传 |

中文项目可用“模块/模块名/设计.md、实现.md”“工程”“规范”“参考”“发行”“本地资料”。同名模块使用同一入口，小功能优先作为章节；仅有设计的模块不补空实现。

模块专用命令、复验与问题归该模块实现；全仓维护只保留通用操作、必要共用工作区台账、集成状态及链接。有效结论替换过期状态，必要历史注明版本与限制，不堆叠流水。保留设计中的未实现要求；素材 SOURCE、manifest 与许可证继续随资产维护。

迁移先核对旧新路径、原文与依赖，再移动并修复链接、锚点、脚本、生成入口、忽略及资源跟踪规则。历史材料保持阶段身份，更新有效索引；缺失证据不能改判通过。历史检查范围见[验收规范](acceptance.md)，不因缺少本地档案阻挡干净检出。

## 可选工作记录

Plan 仅在跨会话接续、路线比较或安排工作时采用，沿用项目本地存储政策，不强制阶段、模板或报告。临时上下文不落盘；必要记录注明日期、范围、状态与未决取舍，完成后有效知识进入所属正文。旧计划不产生新授权。

## 维护边界

写清适用范围、例外与可观察标准；用户新要求更新对应正文并清理重复、冲突和过期内容。客观要求可用可靠脚本检查，审美、信息价值和体验仍须实际检查。
