# 验收、交付与留存

按改动选最小、充分的证据；交付简短如实；只留下有用的东西。命令用项目已有的工程入口，本页不规定工具、报告目录或分支做法。

## 按改动验证

| 改了什么 | 交付前检查 |
| --- | --- |
| 只改文档 | 语义、确认边界、链接和相关入口；跑项目已有的文档检查 |
| 代码或运行资产 | 项目要求的测试和构建 |
| 玩法、画面、操作或启动方式 | 再实际进入受影响的场景，看进入、过程、退出和恢复，以及必要的异常状态 |

- 输入没变、检查仍然有效时复用结果，之后的变化只补受影响的部分。工具出错不算通过。
- 画面要实际看，帧率要实际测，音频要实际听，录像要核对真实时长。文件存在或状态显示完成，不能单独证明画面通过；自动化的短窗口检查不等于真人手感、完整听评或长期稳定。没覆盖到的体验、性能和环境条件如实写出来。
- 独立审核按风险或用户的要求安排，审核者不参与被审的实现。

## 交付

- 写结果、依据、缺口和必要的接续，把本次通过、没解决的失败、没跑的和以前的结果分开写。不另建总结报告。
- 证据注明日期、受测版本、场景和结论的边界。有未提交的改动时，说明实际测的是什么，不只写 HEAD。只补影响判断的环境条件。
- 重跑通过不等于偶发问题的原因已经解决，要如实写。
- 关键失败留下现象、影响、未决问题和必要的诊断。

## 留存

一轮下来，留下来的只有两类，其余都是临时产物。

- **用户的材料**：用户的反馈截图、参考资料、确认过的内容，以及用户点名要留的版本、离线记录或回退副本（只做指定的范围，并核对能恢复）。
- **当轮计划定下要留的**：例如交给用户试玩的版本的截图。留什么、留多少，由当轮的 Goal 或计划写明；没有计划时，只留少量代表性的实机截图，没有画面就不凑图。

怎么存：

- 放在项目指定的一个位置，只存一份，别处不留副本。
- 只用来看的图可以存成有损格式（例如质量约 90 的 JPEG，体积约为 PNG 的十分之一）；逐像素比较用的基线另存无损格式。
- 用 Git LFS 存大文件时，本地有两份（工作区一份、LFS 对象库一份），先想清楚值不值得入库。
- 截图、摘要和哈希不能代替可恢复的备份；开发构建不自动成为留档；留档也不等于可以提交。
- 不默认制作完整源码或资产的快照、验证用的仓库副本、依赖副本、重建包、离线 HTML 或逐帧录像，用户要时才做。

临时产物包括验证截图、评审图、录像、A/B 对照、性能记录、trace、临时脚本和工具缓存：

- **证据不等于留档**：录像、A/B 和评审图是当轮用来判断的，交付后随这一轮删，除非计划或用户点名要留。要留的数字写进交付或计划的结果。
- 写进项目的一个临时目录。并行验证各用一个子目录。工具默认写到系统临时目录的东西（浏览器自动化的临时配置、录屏、trace），也让它们写进这个临时目录，被中断的运行留下的残留才清得到。
- 给 AI 评审画面时，用拼好的对照图和裁切图，少给单张大图：AI 看过的图会存进会话记录，看得越多，会话记录越大。

开了额外的工作树或副本时，它们各带一套依赖、构建和临时产物，这一轮收尾时删掉。

## 清理

一轮收尾时：

1. 列出这一轮的临时产物和大小，给用户看过清单再删。
2. 只按明确列出、先打印出来的清单删。
3. 保护这些东西：最终的验收材料、唯一的源码和素材、用户确认过的内容、许可、必要的回退（删之前确认还能恢复）；正在用的运行、构建和制作依赖；共享的 Git/LFS；还没合入、去向不明的成果；未提交、未跟踪和被忽略的文件；指定的收藏；别的会话的工作区、进程和活跃任务；用户的预览服务。
4. 删完更新引用它们的入口，写明哪些原件已经取不回；历史结论保持当时的身份，不改判通过，也不为旧链接重建整套附件。

材料清理、任务关闭和功能完成分开判断，没做完的事留下接续。

## 文档与工作区接续

- 受影响的设计和工程事实更新到所属正文，其他入口只摘要并链接；历史记录不覆盖当前要求。
- 共用正文不链接只有本地才有的档案，需要时说明存放位置和取法。共用检查默认只查当前正文，历史证据按需显式检查。
- 多分支的项目：沿用指定的主干或共用台账，各分支的正文描述自己的版本，不复制整个仓库的当前状态。接续时用 Git 现场核对路径、未提交的成果和合入关系；分支存在不代表还在用，提交合入了也不代表未提交的成果已经处理。框架不规定台账、主干名称或独立工作区。
- 目录调整按[文档组织](README.md#按模块组织项目文档)核对引用方；新项目的本地材料默认放 `docs/local/`（中文项目 `docs/本地资料/`），已有项目的位置和上传授权继续有效。

## 附录：容易出错的地方

| 做法 | 原因 |
| --- | --- |
| 不按目录名、`ls` 的结果或"没被跟踪"来删 | 按目录反选很容易删掉不该删的；没被跟踪的文件可能是唯一的一份 |
| 删重复件前核对哈希和保留位置 | 名字和大小一样，内容不一定一样 |
| 删工作树或归档前，先确认被忽略的材料去了哪里 | Git 快照不含被忽略的文件，删工作树时里面的产物会跟着没了；宿主可能自己清理关联的工作区 |
| 说释放了多少空间时用前后实测，区分文件大小和磁盘差值，扣掉同期写入 | 估算和实际常常差很多；已删或已恢复的不重复计算 |
| 用宿主支持的操作，不改写会话数据库，不碰其他项目和活跃任务 | 会话记录由宿主管理，改坏了无法恢复 |
