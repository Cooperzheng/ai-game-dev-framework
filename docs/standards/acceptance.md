# 验收与轻量留存

本页统一维护验证、交付和材料留存。具体命令使用项目已有工程入口，不强制固定工具、报告目录或分支策略。

## 按改动验证

- 仅文档修改：核对目标、确认边界、链接和相关入口；运行项目已有文档检查。
- 代码或运行资产：执行项目要求的测试与构建；玩法、画面、操作或启动方式变化，再实际检查受影响入口、场景及必要异常状态。
- 输入未变且已通过的检查，不因总结、归档或清理重复运行；相关输入变化后补受影响检查，不机械重跑全部历史验收。工具异常不能算通过。
- 以原体验目标与认可范围判断完成。技术通过不等于设计确认，短窗口自动化不等于真人手感、完整听评或长期稳定性。独立审核按风险或明确要求开展，只有未参与实现的审核者复核后才称独立审核。

## 交付与留存

交付简述结果、依据、缺口与必要接续，区分本次检查、失败未关闭、未执行和历史结果；不要求固定模板或另写总结报告。重跑通过不自动证明偶发问题根因已解决。

| 情况 | 默认保留 |
| --- | --- |
| 日常迭代 | 对话中的简短交付说明；有效设计与工程知识更新已有正文，不另建验收档案 |
| 大型版本、重要独立模块 | 本地少量代表性实机截图，通常 3–5 张；已有本地索引附一条简短说明。无画面的模块保留简短结果，不凑图 |
| 用户明确要求离线记录、收藏或可恢复副本 | 只制作和检查指定范围，核对恢复所需文件 |

留图注明日期、受测版本、场景与结果边界；未提交工作区如实标注，不能只用 HEAD 代表全部输入。只补影响判断的环境条件，不默认生成逐文件哈希。关键失败保留现象、影响、未解决问题与复验结论，必要诊断材料临时保存。

不默认保存完整源码或资产快照、验证仓库、依赖副本、重建包、离线 HTML 和逐帧录像。截图、摘要与哈希不能代替可恢复备份，正常开发构建不等于验收留档，不以归档为由自动提交。

## 临时输出与历史清理

并行验证使用独立临时目录，避免覆盖仍需排查的原件。任务完成后，同一主题最多留最近两次仍有用的运行，数量是上限；已提取关键结果且无需诊断的输出可在已有授权范围内清理。

删除前核实运行、构建、回归、制作源、许可与当前任务依赖。保护正在使用的目录、未合入或去向不明的唯一成果、指定收藏和最小排障材料；不凭目录名删除，不把取消 Git 跟踪当作删除授权。

历史材料按同一规则收敛，保留关键结论与历史身份，标明已清理原件不再可取，不改判通过。更新有效入口，无需为保持旧链接重建整套附件。共用文档检查默认不遍历历史验收和过程档案；历史证据检查按需显式运行，不作为默认交付门槛。

任务归档可能触发宿主清理关联工作区。归档或移除前核实未提交、未跟踪和忽略文件的去向；Git 快照不保证包含忽略材料。材料清理、任务关闭和功能完成分别判断，未完成事项保留接续。使用宿主支持的操作，不改写会话数据库，不触及其他项目或活跃任务。

## 文档与工作区接续

交付前从共用入口核对受影响的 System、运行说明与实际行为，区分并存模式的适用范围；旧计划的状态和下一步标明历史日期。一个信息维护一份详细正文，其他入口引用；有效设计与技术知识进入对应正文，历史记录不覆盖当前要求。共用文档不链接纯仓库检出中无法取得的本地档案，改为说明本地位置和获取方式；材料是否上传沿用项目授权范围。

项目已有多分支台账时，以项目指定的主干或共用入口维护全仓库接续，分支文档描述各自版本，不逐份复制当前状态。查询时结合现场 Git 核对路径、未提交成果和合入关系；提交已合入不代表未提交成果已处理，分支存在不代表活跃开发。框架不强制建立台账、采用 main 名称或创建独立工作区。
