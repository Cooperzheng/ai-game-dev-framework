# 验收与轻量留存

本页统一维护验证、交付、证据留存与清理，按改动风险取最小充分证据。命令使用项目已有工程入口，不强制工具、报告目录或分支策略。

## 按改动验证

| 改动 | 交付前检查 |
| --- | --- |
| 仅文档 | 核对语义、确认边界、链接与相关入口，运行已有文档检查 |
| 代码或运行资产 | 执行项目要求的测试与构建 |
| 玩法、画面、操作或启动方式 | 加验真实入口、受影响场景及必要异常状态 |

输入未变且检查仍有效时复用，后续变化只补受影响部分；工具异常不能算通过。以原体验目标与认可范围判断结果，技术通过不等于设计确认，短窗口自动化不等于真人手感、完整听评或长期稳定性。独立审核按风险或明确要求开展，审核者不得参与受审实现。

视觉与时序变化检查进入、过程、退出和恢复，并实际查看画面；文件存在或状态完成不能单独证明视觉通过。游戏帧率用实际测量，录制核对真实时长；音频用实际听评，未覆盖的体验、性能和环境条件如实说明。

## 交付与留存

简述结果、依据、缺口与必要接续，区分本次通过、未关闭失败、未执行和历史结果，不另建总结报告。重跑通过不自动证明偶发问题根因已解决。

| 情况 | 默认保留 |
| --- | --- |
| 日常迭代 | 简短交付说明，有效知识更新已有正文 |
| 大型版本、重要独立模块 | 本地少量代表性实机截图，通常 3–5 张；已有索引附简短说明，无画面不凑图 |
| 用户要求离线记录、收藏或回退副本 | 只制作并核对指定范围和恢复所需输入 |

证据注明日期、受测版本、场景与结果边界；有未提交内容时标明有效输入，不只用 HEAD 代替。只补影响判断的环境条件，不默认逐文件哈希。关键失败保留现象、影响、未决问题和必要诊断。

不默认保存完整源码或资产快照、验证仓库、依赖副本、重建包、离线 HTML 或逐帧录像。摘要、截图和哈希不能代替可恢复备份，开发构建不自动成为验收留档，留档不自动授权提交。

## 临时输出与历史清理

并行验证使用独立临时目录，完成后在授权范围内收敛。同一主题默认只留最新一套仍有效的验收媒体；指定基线、必要前后对照与未关闭问题的最小诊断按用途保留。以受测输入、范围和用途判断“最新”，不只看修改时间。

清理前核实保留位置与引用，需保证原字节相同的重复件核对哈希；涉及回退时核实恢复输入与恢复能力，输入未变可复用结果。最终媒体核查完成后，重复录像、上传暂存、无引用中间产物与可再生缓存可在已有授权内移除。

保护最终验收、唯一源码/素材、用户确认、许可和必要回退，以及现用运行/构建/制作依赖、共享 Git/LFS、未合入和去向不明成果、未提交/未跟踪/忽略文件及指定收藏。不凭目录名或取消跟踪删除，不处理清单或授权范围外文件。

更新有效入口，标明已清理原件不再可取；保留历史身份与未决结论，不改判通过，也不为旧链接重建整套附件。空间结论区分文件大小与磁盘实测差值；没有前后测量不估算释放量，同期写入影响归因，历史删除或恢复不重复累计。

归档前核实宿主对关联工作区的清理行为和材料去向，Git 快照未必包含忽略材料。材料清理、任务关闭与功能完成分别判断，未完成事项保留接续；使用宿主支持的操作，不改写会话数据库或触及其他项目、活跃任务。

## 文档与工作区接续

受影响设计与工程事实更新所属正文，其他入口只摘要并链接；历史记录不覆盖当前要求。共用正文不链接纯仓库检出无法取得的本地档案，说明存储位置与取得方式。共用检查默认只查当前正文，历史证据按需显式检查。

多分支项目沿用指定主干或共用台账，分支正文描述各自版本，不复制全仓当前状态。接续结合现场 Git 核对路径、未提交成果与合入关系；分支存在不代表活跃，提交合入不代表未提交成果已处理。框架不强制台账、主干名称或独立工作区。

目录调整按[文档组织](README.md#按模块组织项目文档)核对消费者；新项目本地材料默认用 `docs/local/`，中文等效为 `docs/本地资料/`，已有项目位置与上传授权继续有效。
