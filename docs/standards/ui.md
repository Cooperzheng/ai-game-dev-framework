# 玩家 UI 基础规范

适用于玩家可见界面、文案、布局和交互，不限于某个代码目录。具体功能、视觉方向与用户确认的体验由 PROJECT/System 决定；本规范不预设游戏风格、窗口尺寸或固定菜单。不用于强行删除教程游戏、叙事界面中的必要内容。

## 信息与文案

- 每段可见文字应服务于玩家当前任务、状态、选择、行动代价或必要反馈；无明确用途的文字默认删除，留白不需要补话。
- 不默认添加口号、装饰性短句、重复标题、设计思路、实现说明或自我解释。设计与工程过程留在对应文档。
- 操作优先通过布局、控件、图形和反馈表达；必要说明按需放入提示、帮助或首次引导，不以常驻长指南弥补交互不清。
- 保留清晰的标签、资源代价、风险与错误反馈；精简不能使玩家无法判断或操作。
- 叙事或品牌文案有明确目的时，统一安排层级、位置和样式；未有设计依据时不主动堆叠标语。

| 例子 | 判断 |
|---|---|
| 给空白主菜单补三句宣传语 | 无明确用途时不添加 |
| 在角色面板解释设计理念 | 放入设计文档 |
| 显示升级消耗与资源不足原因 | 属于必要决策信息，应保留 |
| 复杂规则默认占据整屏 | 提供按需展开或合适引导，按已确认体验判断 |

## 层级与操作

- 当前任务、可操作项和状态容易辨认；同类控件反馈一致，关键行动代价可见。
- 不以大量文字替代图形辨识、布局和交互反馈，也不因追求少字而省略必要信息。
- 按项目实际支持范围检查不同窗口与内容状态的可读性、遮挡、溢出、操作可达性；图片适配遵循已确认要求。

## 实际验收

- 查看真实画面，逐项判断文字用途和信息层级，并操作受影响入口与反馈。
- 检查受影响的窗口、内容量及必要异常状态；按改动决定范围，不强制全量检查或固定报告模板。
- 机器检查不能替代体验判断。独立审核方式沿用项目与用户约定，本规范不自动要求派发 Agent。

维护与路由见[规范说明](README.md)。已有项目合并其有效约束与确认设计，不自动替换视觉方向；本文件提供质量基线，不宣称所有下游项目逐项确认过其内容。
