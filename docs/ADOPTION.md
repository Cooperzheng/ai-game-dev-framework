# 接入与升级

接入让 AI 找到用户要求与当前设计，保留有效内容和授权边界；仅接入文档不自动制作游戏、提交或推送。

## 新项目

目标不存在或为空时，用 `node <框架目录>/tools/adopt.mjs --target <目标目录>` 预览，再加 `--apply` 初始化。工具不安装引擎，不创建游戏工程或 Git 仓库。

生成后填写：

- README：项目简介与完整文档入口，只链接已有资料；尚无工程时注明没有运行入口。
- PROJECT：已确认的目标玩家、体验、循环、要求与排除项；另列 AI 当前方案、必要接续与系统入口，未知内容不推定确认。
- 模块：有实际内容时在 `docs/modules/模块名/` 建 `DESIGN.md`，需要持续维护实现时同目录建 `IMPLEMENTATION.md`，不补空正文。

无 Node 时复制 AGENTS.md、docs/ADOPTION.md 及 docs/standards/ 下三份规范；将框架 docs/systems/README.md 保存为游戏 docs/modules/README.md，填写游戏 README 和 PROJECT，不复制框架自身状态。LICENSE 保存为 docs/release/FRAMEWORK-LICENSE.txt，不覆盖游戏许可或推定资产采用 MIT。本地材料默认用 docs/local/ 并加入忽略规则，其他目录按需建立。

## 已有项目与升级

读取目标规则与设计，对照已接入版本及框架的 VERSION、CHANGELOG，保护现有和未提交工作，按差异合并已有正文；具体分工与迁移只按[文档组织](standards/README.md#按模块组织项目文档)维护。

将 AGENTS 中的目录、状态、命令和案例归入所属正文，保留读取条件与权限底线；优先完善已有导航。设计保留用户要求及确认范围，实现与调试归同模块工程正文，必要接续只留当前状态；历史过程保持阶段身份。

旧 Plan、验收附件和重复副本按[验收规范](standards/acceptance.md)及已有授权收敛，不批量补造快照、重跑历史验收或迁移固定格式。核对内容与消费者后才移除重复项，保留唯一成果、许可和必要回退。只处理授权范围，不顺带合入功能、改写历史或撤销项目独立约定。

## 专项规范接入

优先合并项目已有等效规范，AGENTS 保留触发条件和底线，README 维护目录；System 不重复规范正文。仅同步某项规范不等于完整升级，沿用项目命令、本地位置和上传范围，不重建旧证据。无相关改动无需加载相应规范，也不新增空规范、Skill、hook 或流程。

## 完成检查

- 现有入口能定位设计与实现，AGENTS 路由可执行，不要求每轮重读全部资料。
- PROJECT 与 System 区分目标、已确认设计、AI 当前方案及未知项，未扩大确认。
- 有效内容和必要历史结论仍在，删除可取性如实标明，无本次引入的重复正文或坏链。
- 在已有接入信息中记录框架版本、来源 commit、完成与未核实部分；尚无游戏工程时注明。
- 分开说明文档接入与宿主加载验证；未经实测不称自动加载生效，可用新上下文任务观察实际读取，不以 AI 自述为唯一依据。

用 `node <框架目录>/tools/check.mjs <目标目录>` 检查当前 Markdown 目标；默认跳过本地和旧历史过程目录，旧 plans/README.md 仍检查。历史检查显式加 `--local-evidence`，不作为默认交付门槛。按改动核查锚点、生成入口和内容保留，区分遗留问题与本次问题；工具不可用时做等价检查。
