# 接入与升级

接入的目标是让 AI 找到清晰的用户要求和当前设计，保留有效内容与用户授权边界。只接入时不自动制作游戏、提交或推送。

## 新项目

目标不存在或为空时，用 `node <框架目录>/tools/adopt.mjs --target <目标目录>` 预览，再加 `--apply` 初始化。工具不安装引擎、不创建游戏工程或 Git 仓库。

生成后填写：
- README：项目简介与人、AI 共用的文档入口；只链接已有资料，尚无工程时注明没有运行入口。AGENTS 保留工作规则与阅读触发条件，不重复维护目录。
- PROJECT：用户确认的目标玩家、体验、核心循环、要求和排除项；另列 AI 当前整体方案、必要接续信息与系统入口。没有确认的内容不推定确认。
- 模块：有实际模块时在 `docs/modules/模块名/` 建 `DESIGN.md`，仅保存已确认设计与 AI 当前方案；需要持续维护实现时，在同目录建 `IMPLEMENTATION.md`。不预建空模块、空实现或整套目录。

无 Node 时复制 AGENTS.md、docs/ADOPTION.md 及 docs/standards/ 下三份规范；将框架的 docs/systems/README.md 模板说明保存为游戏的 docs/modules/README.md，并新建上述项目 README 和 PROJECT，不复制框架自身的介绍或状态。框架 LICENSE 保存为 docs/release/FRAMEWORK-LICENSE.txt，不覆盖游戏 LICENSE，也不推定游戏或资产采用 MIT。本地记录默认使用 docs/local/，加入项目忽略规则；工程、参考和具体模块按需建立。

## 已有项目与升级

1. 读取目标适用规则、设计与现有工作，保护未提交变更；升级比较采用版本与 CHANGELOG，不覆盖正文。
2. 按[文档组织](standards/README.md#按模块组织项目文档)整理：PROJECT 保存方向；每个模块在同一目录中维护设计与按需建立的实现；共用工程、规范、参考、发行及本地材料各有归属。文件名可本地化；既有项目按已授权范围迁移，保护原文并同步总览、AGENTS 与所有消费者。
3. 合并旧项目目标与状态时，PROJECT 只留影响接续的当前信息。设计正文中的技术实现和调试转入同模块实现，临时开发过程按需留在本地工作记录，保留有效知识；不因它们被 AI 记录就提升为确认设计。
4. 旧 Plan、验收报告与证据保留历史身份，按轻量留存规范和已有授权收敛，不要求补齐或批量迁移到新的固定格式。它们不承担当前设计的权威来源；真正仍有效的用户要求应归入 PROJECT 或 System。
5. 核对转移内容再移除重复设计正文，同步文档、脚本与生成入口中的引用。保护仍需使用的原始材料及历史身份，外部大型材料沿用项目存储政策；不重跑全部历史验收。
6. 只处理本轮授权的目录或分支，不顺带合入功能或改写历史。保留目标项目独立约定的流程与权限；框架不强制 Plan、分支策略、默认 commit 或报告模板，也不借升级撤销用户另行明确的约定。
7. 0.1.4补充交付收尾与证据一致性规则：合并到已有AGENTS约定，按影响核对运行说明和验收入口。无需为历史结果补造受测快照，不批量重跑无关验收；hook由项目选择，初始化不安装hook，也不修改宿主信任或用户级配置。

8. 0.1.5明确文档职责：优先完善已有 README 的文档入口，已有等效总览则沿用，不额外新建 AI 专用目录。将 AGENTS 中的目录、状态、长案例和模板移至对应文档，保留工作规则、权限边界及适用条件；技术架构不覆盖设计授权。核对原有锚点与引用，不因精简丢失有效约束或扩张适用范围。

## 专项规范接入

0.1.6 增加专项规范路由：新项目生成有实际内容的规范说明与 UI 基础规范，不安装 Skill 或 hook。已有项目优先合并等效规范，保留用户确认设计与本地审核要求；AGENTS 只留触发条件、核心底线与路径，README 补目录，System 不重复维护规范。仅同步这些内容不等于完整升级其他规则。无 UI 的任务无需加载 UI 规范，也不预建其他空规范。

0.1.7 将验收与轻量留存统一到独立规范：替换默认保留整套记录、快照和副本的旧条款，保留必要验证、真实结果与依赖保护。日常迭代不另建档案，重要模块通常留 3–5 张图；共用文档检查不默认遍历历史档案。已有项目沿用自己的命令、存储位置和上传范围，不为同步规范重建旧证据。多工作区沿用指定的共用台账，归档前核实忽略文件去向。

0.1.8 按模块收拢设计与实现，完整导航只在 README 维护；模块命令、复验和未决问题进入该模块实现，全仓维护只保留通用操作及集成状态。迁移同时修复路径、锚点、脚本、生成入口、忽略与资源规则；历史展示明确阶段身份，原图和有效证据保持完整。模板不自动移动已有项目，也不生成空模块或空实现。

## 完成检查

- 文档总览可定位设计、已有技术与历史资料；AGENTS 的阅读触发条件仍可执行，不要求每轮读取全部文档。

- 分开报告“文档已接入”与“宿主加载已验证”。链接存在或提示用户读取不等于验证自动加载；未实测时写加载未验证，并给出显式读取提示。可通过一次新上下文任务观察是否实际读取相关依据和遵循规则，不以 AI 自述作为唯一证据。
- PROJECT 与 System 能回答目标是什么、哪些已确认、哪些由 AI 自主调整；未知项列明，确认范围没有被扩大。
- 有效设计、技术知识与必要历史结论保留，已清理原件如实标明，没有重复的当前设计正文或本次引入的坏链。
- PROJECT 的简短接入信息记录框架版本、来源 commit、已完成与未核实部分；目标尚无工程时说明，不把文档接入完成当作游戏可运行。

用 `node <框架目录>/tools/check.mjs <目标目录>` 检查当前 Markdown 目标；默认跳过 docs/local/ 及中文 docs/本地资料/，同时兼容旧 docs/acceptance/ 和 docs/plans/ 过程档案（保留旧 plans/README.md 说明检查），需要检查历史时显式加 --local-evidence。按改动核查锚点、生成入口和内容保留。遗留问题与本次问题区分。工具不可用时可等价检查，方法由实际任务决定。
