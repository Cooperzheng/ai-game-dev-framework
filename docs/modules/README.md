# 模块设计与实现模板

本页是模板说明，不是游戏的模块目录。游戏里的每个模块放在 `docs/modules/模块名/`（或本地化的 `docs/模块/模块名/`），设计和实现在同一个目录，分工见[文档组织](../standards/README.md#按模块组织项目文档)。已有项目沿用有效的正文，不为凑齐文件去建空的实现。

## 设计：`DESIGN.md`（或 `设计.md`）

写玩家能做什么、规则怎么运作、预期的感受和当前的设计。代码路径、状态机、依赖、算法和实现步骤写在实现文档里。

```markdown
# 模块名称

## 已确认设计
用户明确的体验目标、规则和排除项，简要注明来源和认可范围。
已确认、还没实现的要求保留，并注明差距；没有明确确认就写"暂无"，不补造。

## AI 当前方案
当前采用的功能、操作、反馈、数值，以及和其他模块的玩法关系。
写清玩家体验上的差别，按需注明已实现、尚未实现或效果未达标。
```

两部分怎么区分，见 [AGENTS 的设计依据](../../AGENTS.md#设计依据)。

- 用户认可了某项 AI 方案时，只把认可的那部分移到"已确认设计"，不在两处重复维护。
- 还没采用的候选方案不写成当前规则；尝试过程需要时记在可选的工作记录里，必要的技术知识写在代码注释或已有的工程说明里。

## 实现：`IMPLEMENTATION.md`（或 `实现.md`）

需要持续维护实现时才建。写实现入口、必要的参数和接口、制作前提、专用检查和有效的复验结论。

- 复验注明日期、版本或草稿身份、检查范围、结果和未决问题；新结论替换失效的状态，不逐轮追加报告。
- 跨模块的约定由工程总览维护，这里引用；图像的来源和许可保留在资产目录。
