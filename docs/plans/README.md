# 阶段计划

目标明确、影响有限的小修无需落盘。大功能交付与复杂工作按需在 active 建立计划；复杂内部工作有 Plan 不等于必须创建大功能验收档案。

```markdown
# 本轮功能简介

- 状态：进行中
- 关联设计：对应系统文档及版本

## 目标与范围
体验目标、当前差距、本轮包含与排除内容。

## 设计依据与关键未知
已确认要求、硬约束、暂定方案；最需要先验证的假设。

## 执行与验证
必要阶段、首个可观察结果、关键依赖及失败后的备选方向。

## 验收条件
原始目标如何判定；实际入口、操作场景和适用回归。项目已有预算/停止条件。

## 进度与重要决策
仅记录影响接续的进度、取舍与阻塞，不堆命令日志。

## 收束
目标兑现情况、遗留问题和交付报告链接。
```

状态流转：进行中 ↔ 阻塞；结束后为已完成、未达标收束或已取消。阻塞写明恢复条件并留在 active；终态移入 completed 并修正链接。取消前未产生交付结果时不强制创建空验收档案。

假设被证伪时更新路线，原目标不能为迎合结果擅自降低。经用户明确调整的目标记变更依据；报告保留最初目标、批准的变化和最终评价范围。

验收报告引用归档计划的路径及当时 commit；未提交时在交付目录保存小型方案快照。结束后续作建立新计划或明确的新阶段，不无标记地重写旧计划。
